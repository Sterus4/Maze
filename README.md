# Лабиринт

Игра-лабиринт: терминальная игра и просмотрщик графа на Python 3.10+,
а также Android-прототип комнат на Godot. Для Python-версий сторонние
библиотеки не нужны.

## Android: обзор комнаты поворотом телефона

Первый игровой прототип расположен в `android-game/`. Готовый APK после
сборки: `build/Maze-Rooms-debug.apk`. В нём есть обзор на 360° поворотом
телефона или пальцем, выбор двери, переходы, сохранение и выход из лабиринта.
Обзор телефоном и пальцем работает одновременно. В меню доступны автоматическая,
горизонтальная и вертикальная ориентации экрана; интерфейс перестраивается под них.
Количество комнат вводится прямо на телефоне (1–5000); есть кнопки 12/40/100.
Новые графы генерируются локально; кратчайший путь задаётся от 10% до 90%
с шагом 10% (по умолчанию 30%). Дверь открывается,
камера плавно проходит в заранее подготовленную соседнюю комнату, дверь закрывается.

Подробности установки, управления, ограничений первого этапа и сборки —
в [android-game/README.md](android-game/README.md).

## 3D-просмотрщик

```powershell
python viewer.py
python viewer.py --rooms 100 --path-percent 30 --seed 42
```

Альтернативный запуск: `python -m maze.viewer`. Нужен Python с Tkinter
(обычно включён в установщик Python для Windows). Проверка: `python -m tkinter`.
На Linux Tkinter может устанавливаться отдельным системным пакетом.

В окне комнаты представлены точками, а существующие переходы — линиями.
Пружинный алгоритм размещает вершины в трёхмерном пространстве: связанные
комнаты притягиваются, остальные отталкиваются. Перспективная камера позволяет
осматривать граф с разных сторон и летать внутри него. Это обзор графа;
физические стены, столкновения и ограничения строительства не моделируются.
Пересечение линий на экране не создаёт дополнительного перехода.

Зелёная точка — вход, розовая — выход, золотые точки и линии — основной путь,
голубые точки — ответвления. В лабиринте из одной комнаты вход и выход
совпадают и отмечены зелёным. Подсветку пути и номера можно выключить.

Щёлкните по сцене, чтобы передать ей управление клавиатурой:

| Управление | Действие |
| --- | --- |
| `W` / `S` | Полёт вперёд / назад относительно взгляда |
| `A` / `D` | Полёт влево / вправо |
| `Q` / `E` | Вниз / вверх по мировой вертикали |
| `Shift` | Ускорение в 3 раза |
| Правая кнопка мыши + движение | Поворот камеры |
| Стрелки | Поворот камеры с клавиатуры |
| Колесо мыши | Перемещение вперёд / назад |
| `Home` / `F` | Вернуть весь граф в кадр |
| `P` | Включить / выключить основной путь |
| `L` | Включить / выключить номера комнат |
| Щелчок по точке | Выбрать комнату и показать её соседей |
| Двойной щелчок / `Enter` | Подлететь к выбранной комнате |
| `Esc` | Остановить текущее движение |

Количество комнат, процент пути, seed и скорость меняются в правой панели.
«Построить лабиринт» использует введённые параметры, «Новый случайный лабиринт»
выбирает новый seed. После построения фактический seed отображается в поле;
одинаковые параметры и seed повторяют и граф, и его размещение.

Просмотрщик поддерживает 1–1000 комнат; для комфортного первого знакомства
рекомендуется 100. Раскладка выполняется в фоне и требует O(N²) работы на
итерацию; большие графы строятся заметно дольше. Рисование выполняется на CPU
через Tk Canvas с перспективной проекцией и упрощённым порядком отрисовки,
без аппаратного 3D-движка. Для больших сцен и будущих стен нужен другой рендерер.

## Запуск

Из папки проекта:

```powershell
python main.py
```

По умолчанию: 100 комнат, кратчайший путь — 30 комнат, новый случайный
лабиринт при каждом запуске. Можно также запускать `python -m maze`.

```powershell
python main.py --rooms 150 --path-percent 40
python main.py --rooms 100 --path-percent 30 --seed 42
python main.py --help
```

`--rooms` — целое число от 1. `--path-percent` — число больше 0 и до 100
включительно (дробная часть через точку). Длина пути округляется до ближайшего
целого, половины вверх. Для нескольких комнат минимум — две комнаты,
для одной — одна. Вход и выход входят в длину пути: 30 комнат означают
29 переходов между комнатами. Выход наружу не считается переходом между комнатами.

Значение seed отображается при старте. Чтобы повторить лабиринт, используйте
его с теми же параметрами комнат и процента.

## Управление

Введите номер двери от 1 до 4. Рядом с соседними комнатами отмечается,
посещали ли вы их. Номера комнат перемешаны и не указывают путь к выходу.

| Команда | Действие |
| --- | --- |
| `назад` / `b` | Вернуться на один шаг по истории перемещений |
| `осмотр` / `l` | Повторно показать текущую комнату |
| `статус` / `s` | Показать число посещённых комнат и переходов |
| `подсказка` / `h` | Узнать следующую дверь на кратчайшем пути от текущей комнаты |
| `помощь` / `?` | Показать справку |
| `выход` / `q` | Завершить игру без победы |

Для победы нужно пройти через дверь «ВЫХОД ИЗ ЛАБИРИНТА».
Внешняя дверь входа отмечает начало игры; выйти через неё нельзя.
`Ctrl+C` и конец ввода корректно завершают приложение.

Просмотр характеристик или полного решения без запуска игры:

```powershell
python main.py --seed 42 --inspect
python main.py --seed 42 --solution
```

## Генерация

1. Перемешиваем номера всех комнат. Берём заданное число комнат и соединяем
   их в цепочку от входа до выхода.
2. Остальные комнаты последовательно присоединяем к случайным уже добавленным
   комнатам со свободной дверью. Каждая новая комната наследует корень
   ответвления — единственную комнату основной цепочки.
3. Случайно добавляем рёбра внутри групп с одинаковым корнем, включая сам
   корень. Учитываем лимит дверей, запрещаем петли в одну комнату и повторные
   рёбра. Циклы возможны, но не обязательны: их число зависит от параметров
   и seed. При 100% комнат на основном пути ответвлений и циклов нет.

Все комнаты достижимы. У каждой комнаты от 1 до 4 дверей. **Внешние двери
входа и выхода включены в этот лимит**: у крайних комнат основной цепочки
есть минимум одна внутренняя и одна внешняя дверь. В лабиринте из одной
комнаты есть две внешние двери — вход и выход.

Каждое ответвление соединено с основной цепочкой только в одном корне.
Поэтому даже закольцованный проход не может сократить расстояние между
двумя комнатами основной цепочки. Кратчайший путь всегда имеет заданную
длину. Число независимых циклов вычисляется как `E - V + 1`, где внешние
двери не входят в `E`.

Генерация выполняет линейное число попыток соединения комнат; число дверей
ограничено четырьмя. Ожидаемое время и память — O(N). Поиск кратчайшего пути
в ширину также занимает O(N).

## Структура и проверки

- `maze/core.py` — конфигурация, комнаты, генератор, поиск пути и состояние игры.
- `maze/cli.py` — ввод и вывод в терминале.
- `main.py` — точка запуска.
- `viewer.py` и `maze/viewer.py` — запуск и оконный 3D-просмотрщик.
- `maze/spatial.py` — размещение графа, перспектива, отсечение и свободная камера.
- `tests/test_maze.py` — проверки генератора, игровой логики и терминального интерфейса.
- `tests/test_spatial.py` — проверки размещения, проекции и перемещения камеры.
- `tests/test_viewer_gui.py` — интеграционная проверка окна, включается отдельно.

Для будущего UI можно импортировать `MazeConfig`, `generate_maze`, `Game`
из `maze`: ядро не читает ввод и ничего не печатает.

```powershell
python -m unittest discover -s tests -v
```

Проверки охватывают связность, симметрию дверей, их лимит, точную длину пути,
отсутствие сокращений через ответвления, циклы, тупики, воспроизводимость,
крайние параметры и прохождение игры до победы.

Дополнительно проверяются воспроизводимость 3D-размещения, сохранение связей,
отсечение линий позади камеры, движение и попадание всего графа в кадр.
Интеграционный тест окна требует графического рабочего стола:

```powershell
$env:MAZE_GUI_TESTS = "1"
python -m unittest discover -s tests -p test_viewer_gui.py -v
Remove-Item Env:MAZE_GUI_TESTS
```
