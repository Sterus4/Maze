# Maze Rooms — Android-прототип 0.3

Игра от первого лица: игрок стоит в центре квадратной комнаты, осматривается
поворотом телефона или пальцем и выбирает одну из 1–4 дверей. Камера находится
на высоте 1,65 м. Входная дверь тоже входит в лимит четырёх дверей.

## Установка и управление

Готовая сборка находится в `../build/Maze-Rooms-debug.apk`. Скопируйте APK на
телефон и откройте его для установки. Android при необходимости предложит
разрешить установку для приложения, через которое открыт файл.

Это отладочная локальная сборка, без Google Play и без доступа к интернету.
APK содержит ARM64 для современных телефонов и x86_64 для эмулятора. Требуются
Android 7.0+ и OpenGL ES 3.0. Python на телефоне не требуется.

1. Держите телефон вертикально или горизонтально. Введите количество комнат от 1 до 5000
   или нажмите 12/40/100, затем «Новый лабиринт».
   Касание поля открывает встроенную цифровую клавиатуру: первое нажатие цифры
   заменяет старое число, C очищает поле, ⌫ удаляет цифру, «Готово» применяет ввод.
   Кнопками −10% / +10% задайте долю комнат кратчайшего пути: 10–90%,
   по умолчанию 30%. Значение применяется при создании нового лабиринта
   и сохраняется вместе с ним.
2. Поворачивайте телефон, чтобы рассматривать стены, пол и потолок.
3. Либо проводите пальцем по свободной части экрана для обзора.
4. Коснитесь двери для перехода. Другой способ: наведите на дверь прицел
   и нажмите «Перейти».
5. Дверь откроется, камера плавно пройдёт в соседнюю комнату, дверь закроется.
   Дверь, из которой пришли, будет позади; она возвращает в предыдущую комнату.
6. Найдите золотую дверь «Выход», чтобы завершить игру.

«Центрировать» выставляет удобное начальное направление относительно положения
телефона. Поворот телефона и обзор пальцем доступны одновременно, переключателя
между ними нет. Если датчики недоступны, используйте обзор пальцем.
Для сенсорного обзора желательны гироскоп и акселерометр.

Кнопка «Экран» в меню переключает «Авто» → «Горизонтально» → «Вертикально».
В автоматическом режиме интерфейс следует повороту телефона; два других режима
фиксируют выбранную ориентацию. Настройка сохраняется отдельно от прохождения.
В вертикальном режиме панели и подсказки перестраиваются под ширину экрана.
После смены ориентации приложение кратко ждёт обновления датчиков и выравнивает
взгляд; при необходимости можно нажать «Центрировать».

Переходы, посещённые комнаты и последнее прохождение сохраняются локально.
«Продолжить» возобновляет его, «Новый лабиринт» сбрасывает прогресс и генерирует
новый граф заданного размера. Внешняя дверь «Вход» не завершает игру. Номера комнат,
расположение дверей и оформление сохраняются при возвращении.

## Возможности и ограничения

- Генерация на телефоне: 1–5000 комнат, 10–90% комнат в кратчайшем пути с шагом 10%
  (округление половин вверх, минимум две комнаты при размере больше одной).
  От одного до четырёх дверей, ветви и циклы без сокращения основного пути.
- Настоящие 3D-сцены текущей комнаты и её непосредственных соседей:
  одновременно не больше пяти комнат, независимо от размера графа.
- Поворот камеры на основе встроенного Godot MobileVRInterface: объединение
  гироскопа и гравитации. Из интерфейса берётся только ориентация; viewport XR
  выключен, перемещение головы не используется. Камера телефона не нужна.
- Обзор пальцем, касание двери, прицел, открывание и закрывание дверей,
  плавный проход без затемнения, победа, сохранение всего графа и прогресса.
- На компьютере: перетаскивание левой кнопкой мыши или стрелки, Enter — пройти,
  C — центрировать, Escape — меню.

Генератор перенесён на GDScript с тем же алгоритмом, что в Python; одинаковый
seed между языками не означает одинаковый граф из-за разных генераторов случайных чисел.
Комнаты по-прежнему представляют произвольный граф, а не единый план здания.
Соседние комнаты поворачиваются так, чтобы нужные проёмы совпали; закрытые двери
скрывают остальную геометрию. После прохода подготавливаются следующие соседи.
На время анимации (около 2,2 секунды) камера направлена вдоль прохода;
свободный обзор и выбор следующей двери доступны после завершения.
Физическое перемещение телефона и свободная ходьба пока не используются.

## Подготовка контрольных данных Python

Для обычной игры экспорт не требуется: граф генерируется в приложении.
Встроенный каталог сохранён для тестов и совместимости с сохранениями версии 0.1.

Из корня репозитория:

```powershell
python scripts/export_android_mazes.py
```

Свой контрольный лабиринт вместо трёх стандартных (меню новых игр использует
встроенный генератор GDScript):

```powershell
python scripts/export_android_mazes.py --rooms 100 --path-percent 30 --seed 123
python scripts/build_android.py --skip-data-export
```

Экспорт сохраняет все связи, вход, выход, число комнат кратчайшего пути,
а также постоянное назначение дверей четырём стенам. Данные находятся в
`data/mazes.json`, схема — версия 1. Логика Godot проверяет связность,
обратные связи, лимит дверей и корректность данных перед использованием.

## Сборка на Windows

Нужны Python 3.10+, JDK 17+ и установленный Android SDK с Platform Tools
и Build Tools. Скрипты не меняют глобальные настройки Godot или политику
PowerShell. Инструменты и их локальные настройки находятся в `.tools/`.

```powershell
python scripts/fetch_godot.py
python scripts/build_android.py
```

Первый скрипт загружает официальный Godot 4.7.2, проверяет SHA512 архива движка
и извлекает Android debug-шаблон частичными HTTP-запросами. Остальные платформы
из большого архива шаблонов не скачиваются. Сторонние Python-пакеты не нужны.
Второй скрипт экспортирует данные, импортирует проект, проверяет игровую логику
и создаёт подписанный отладочным ключом APK в `build/`.

При нестандартных путях:

```powershell
python scripts/build_android.py --android-sdk "C:\path\to\Android\Sdk" --java-sdk "C:\path\to\jdk"
```

Для изменения и запуска на компьютере откройте `project.godot` в Godot 4.7.2
или выполните из корня:

```powershell
& .\.tools\godot\Godot_v4.7.2-stable_win64.exe --path android-game
```

## Проверки

```powershell
python -m unittest discover -s tests -v
& .\.tools\godot\Godot_v4.7.2-stable_win64_console.exe --headless --path android-game --script res://tests/test_state.gd
& .\.tools\godot\Godot_v4.7.2-stable_win64_console.exe --path android-game --script res://tests/smoke_scene.gd
```

Проверяются перенос связей из Python, кратчайшие пути, движение через двери
и обратно, завершение игры, сохранение, ошибочные данные и обзор пальцем.
Проверка сцены дополнительно запускает 3D-рендерер, выбирает дверь лучом,
переходит в комнату и обратно и сохраняет изображения в `build/`.

Физические датчики конкретного телефона требуют проверки на самом телефоне:
повороты вправо/влево, вверх/вниз, полный оборот, центрирование и возврат из
фонового режима. Эмуляция и тесты математики не заменяют эту проверку.

Сборка проверена на Android 11 в эмуляторе: установка APK, отображение комнаты,
касание двери, обзор пальцем, жест с отпусканием поверх интерфейса, реакция на
виртуальный гироскоп и восстановление прогресса после обновления приложения.
Для версии 0.2 дополнительно проверены кнопки 40/100, ввод 24 встроенной цифровой
клавиатурой, создание нового графа и анимированный проход без затемнения.
Для версии 0.3 проверены переключение горизонтальной/вертикальной ориентации
на Android, сохранение режима после перезапуска, обзор пальцем и виртуальным
гироскопом в вертикальном режиме. Проверка сцены проверяет размещение меню
и игровых кнопок при повороте окна в обе стороны.
Проверки игровой логики Godot: 809 проверок, включая генератор до 5000 комнат
и стыковку всех 16 сочетаний стен. Проверка сцены проверяет движение камеры,
створку, повторное использование соседней комнаты, возврат и сохранение графа.

## Файлы

- `scripts/maze_state.gd` — независимая игровая логика и сохранение.
- `scripts/maze_generator.gd` — генерация новых лабиринтов на устройстве.
- `scripts/look_controller.gd` — сенсорная ориентация, обзор пальцем, центрирование.
- `scripts/room.gd` — геометрия комнаты, двери и их оформление.
- `scripts/game.gd` — интерфейс, выбор дверей, переходы и жизненный цикл.
- `export_presets.cfg` — параметры Android-сборки.
- `tests/` — проверки, не включаемые в APK.

Документация движка: [Android export](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_android.html),
[MobileVRInterface](https://docs.godotengine.org/en/stable/classes/class_mobilevrinterface.html).
